# 週のリズム（曜日別テンプレート）

曜日ごとに、日次ノートの最初に入れる予定を決めておく機能。週の配分（例: 月火水は PhD 8h・副業 2h、木金は 5h・5h）を毎朝手で入力しなくて済むようにする。設定画面は `/scheduling/rhythm`。

これは段階1にあたる。週予算に対する実績の集計（段階2）と、週内の自動再配分（段階3）は含まない。

## 枠の種類

| 種類 | ノートに入る行 | 主な項目 |
| --- | --- | --- |
| 予定枠 | `/schedule` の時間枠（条件型） | プロジェクト（任意）、作業タイプ、名前（任意） |
| 固定予定 | 固定予定の行（`timed_line`、`kind: event`） | 名前（必須） |
| 休憩 | 休憩の行（`timed_line`、`kind: break`） | 名前（必須） |

- 予定枠は、`/schedule` の候補でプロジェクト（プロジェクトなしなら「自動」）を選んだときと同じ形の行になる。プロジェクトありなら `filter.project_ids` にそのプロジェクトを入れ、`filter.work_types` は空にする。プロジェクトなしなら `filter.work_types` に作業タイプを入れる。行の `work_type` は枠の作業タイプ。
- 行のタイトルは「名前（プロジェクト名）」。名前がなければプロジェクト名、どちらもなければタイトルなし。
- 「動かさない」（`locked`）は、段階3の再配分で動かさない枠（実験・Life など）の印。現時点では保存と集計だけで、ノートの行には影響しない。
- 同じ曜日の予定枠どうしは重ねられない（端が接するのは可）。ノートは重なった時間を一度だけ数えるので、重なりを許すと週の合計とトリアージ配分がノートと食い違うため。固定予定・休憩は予定枠の中に置ける（例: 9:00–16:00 の実験枠と 12:00–13:00 の昼食）。
- 1曜日48件、全体200件まで。時刻は `HH:MM`、開始は終了より前（日をまたぐ枠は不可）。

## ノートへの挿入

- 予定（固定予定・休憩・`/schedule`）がまだないノートを開いたとき、その曜日に枠があれば「週のリズム（水曜）の予定 N件をノートに入れられます」と「ノートに挿入」を表示する。日次計画画面とダッシュボードのノートカードの両方で使える。
- 挿入した行は、メモ（既存の本文）の後ろに時刻順で追加する。末尾の空行は除く。行の ID は挿入のたびに新しく作る。
- 挿入した後はノートの通常の行として編集・削除・自動スケジュールができる。ノートは自分の行を持つので、テンプレートを後から変えても挿入済みのノートは変わらない。
- 予定が1件でもあるノートには表示しない（重複を防ぐため）。テンプレートを読み込めないときも表示しないだけで、ノートの編集は止めない。
- 曜日はノートの日付（`YYYY-MM-DD`）から計算し、ブラウザーのタイムゾーンに依存しない。

## 週の合計とトリアージへの反映

- 予定枠の時間から、同じ曜日の固定予定・休憩と重なる時間を除いて、曜日別・プロジェクト別に合計する。ノートの自動スケジュールも固定予定・休憩の時間にはタスクを置かないため。
- 「トリアージ配分に反映」は、トリアージの実働時間（週の容量 − 会議バッファ）が予定枠の合計になるよう週の容量を設定し、プロジェクト配分を合計の割合（1%単位、最大剰余法で合計100%）に置き換える。プロジェクトなしの予定枠は Inbox の配分になる。会議バッファ・作業種別の上限・生成間隔などほかの設定は変えない。
- 反映できるのは保存済みの内容だけ。進行中ではないプロジェクトの予定枠があるときは反映しない（トリアージ設定画面は進行中のプロジェクトしか配分を表示しないため）。

例: 提案した週（PhD 40h・副業 16h・Life 3.5h、計 59.5h）は、配分 PhD 67%・副業 27%・Life 6%、会議バッファ 0h なら週の容量 59.5h になる。

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/weekly-rhythm` | テンプレート（曜日・開始時刻順）と集計 |
| PUT | `/api/weekly-rhythm` | テンプレート全体を置き換える（`{"blocks": []}` で消去） |
| POST | `/api/weekly-rhythm/apply-to-triage` | 集計をトリアージ容量設定へ反映し、更新後の設定を返す |

- `weekday` は Python の `date.weekday()` と同じ 0 = 月曜 … 6 = 日曜。画面は日曜始まりで表示する。
- PUT は所有していないプロジェクトを含むと 400、予定枠の重なりも 400（どの曜日・時刻かを日本語で返す）、形式の誤りは 422。
- 置き換えは最後に保存した内容が勝つ（リビジョンによる競合検出はしない）。設定画面は1人で使う前提のため。

## データ

`weekly_rhythm_blocks`（マイグレーション `042_add_weekly_rhythm.sql`）にユーザーごとの行を保存する。プロジェクトを削除しても枠は残り、`project_id` が NULL（プロジェクトなしの予定枠）になる。曜日の時間の構造を保つため。ユーザーを削除すると枠も削除する。RLS は所有者の行だけを許可する。

9月に削除した `slot_templates`（031）は、ノート導入前の時間枠スケジューラーの入力で、ノートからは読まれていなかった。週のリズムはノートに行を挿入するためのもので、ノートが唯一の読み手になる。

## 展開手順

1. `042_add_weekly_rhythm.sql` を MigrationManager で適用する（追加のみで、旧APIはこのテーブルを読まない）。
2. API、次に Web をデプロイする。追加の環境変数やパッケージは不要。
3. `/scheduling/rhythm` で枠を保存し、予定のない日のノートで「ノートに挿入」が表示されることを確認する。

ロールバックは先に Web と API を戻してから `042_add_weekly_rhythm_rollback.sql` を適用する。テンプレートは削除されるが、挿入済みのノートの行は残る。
