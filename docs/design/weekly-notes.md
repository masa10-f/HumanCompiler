# 週次ノート

1週間ごとに1つ持つ、自由に書けるノート。日次ノートが「その日の予定と記録」なのに対して、週次ノートは「今週の目標」「振り返り」「来週へ持ち越すこと」を1か所にまとめるためのもの。画面は `/notes/weekly`（ノート一覧の「週次ノート」タブ）。エージェントは MCP の `get_weekly_note` / `list_weekly_notes` で読める。

## 週の決め方

- 週は、始まりの日（`week_start`、`YYYY-MM-DD`）から7日間。
- **週の始まりの曜日はユーザーごとに選ぶ**（日曜〜土曜のどれでも。`user_settings.week_start_day`、既定は日曜。週のリズムの画面も日曜始まりで表示している）。設定ページの「週の始まり」で変える。週次ノートの画面には今の設定と、設定ページへのリンクを出す。
- 曜日を2つに絞らないのは、週次レポートが開始日を自由に選べる（その日から7日間を集計する）のと同じく、週の区切りは人によって違うため。
- 「今日」は日本時間で決める（日次ノートと同じ）。
- **書いたノートは、書いたときの7日間のまま。** 設定を変えても、既存のノートの期間は変えない（移すと、2つの週がまとまったり、日がはみ出したりするため）。ノートのない週だけが新しい設定に従う。

### ある日の週を決める順番

`weekly_notes.resolve_week` が、Web・MCP の両方で次の順に探す。

1. その日に始まるノート（「最近の週次ノート」から開いたとき、必ずそのノートになる）。
2. 今の設定で、その日を含む週のノート。
3. 設定を変える前に書いた、その日を含むノート（例: 日曜始まりで書いた 11/1〜11/7 のノートは、月曜始まりにした後も 11/4 から開ける）。
4. どれもなければ、今の設定でのその日の週（ノートなし）。

新しいノートは、今の設定での週の始まりの日にだけ作れる。設定を変えた直後は、新しい週と古いノートの期間が重なることがある（最大6日。例: 月曜始まりの 10/26〜11/1 と、日曜始まりの 11/1〜11/7）。重なった日は上の順番で決まる。

## 画面

- `/notes/weekly?week=YYYY-MM-DD` で開く。`week` は週のどの日でもよい。省くと今週。
- 前の週・今週・次の週で移動する。見出しは「今週」「先週」「2週前」などと、「2026年11月1日（日）〜7日（土）」。期間はサーバーが決めた週（上の順番）を表示し、「前の週」はその週の始まりの前日、「次の週」は終わりの翌日を含む週を探す（設定を変えた後でも、古いノートを飛ばさないため）。
- 本文はプロジェクト・Goal・Task のノートと同じリッチテキストエディター（`ContextNotePanel`）。保存は入力の 500ms 後で、`expected_updated_at` で競合を検出する。別の場所で変わっていたら、ほかのノートと同じ競合のバナー（最新を読み込む／この内容で上書き）を出す。
- 週を移ると、エディターを作り直す（React の `key`）。保存待ちの入力は、作り直す前に元の週へ保存する。
- 本文の上に「この週の日次ノート」を7日分並べる。各日はその日の日次ノートへのリンクで、日次ノートのタイトル（無ければ「ノートなし」）を出し、今日を強調する。広い画面では横一列、スマホでは縦の一覧。横には「最近の週次ノート」（新しい週から8件）を出す。

## API（Web）

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/weekly-notes` | 空でない週次ノートを新しい週から。`before`（その日より前に始まる週）、`limit`（1〜50、既定20）。`next_cursor` を次の `before` に渡す |
| GET | `/api/weekly-notes/{day}` | `day` を含む週のノート（上の順番）。無ければ空のノート（`id`・`updated_at` が `null`）を返し、行は作らない。`week_start`・`week_end` がその週 |
| PUT | `/api/weekly-notes/{week_start}` | `{content, content_type?, expected_updated_at?}`。その日に始まるノートを更新する。無ければ作る |

週の始まりの設定は、ほかのユーザー設定と並べて置く。

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/user/settings/week-start` | `{week_start_day}`（`sunday` … `saturday`）。設定したことがなければ `sunday` |
| PUT | `/api/user/settings/week-start` | 週の始まりを変える。設定の行がなければ作る。ほかの値は 422 |

- PUT で新しく作るとき、`week_start` が今の設定での週の始まりでなければ 400（「週の開始日（水曜日）を…」）。既存のノートは、設定と違う曜日に始まっていても更新できる。
- `expected_updated_at` が保存済みの値と違えば 409 `{message, current_updated_at}` で、何も書かない。ノートのない週を開いた編集画面は比べる `updated_at` を持たないので、最初の保存では代わりに `expect_new: true` を送る。その間に別のタブや端末がその週のノートを作っていれば同じ 409 になり、上書きしない。どちらも省くと上書き（競合のバナーの「上書き」）。両方を送ると 422。
- 見える内容のないノート（エディターの `<p></p>` など）は `""` として保存し、一覧に出さない。
- `content_type` は `html`（既定）か `markdown`。本文は 1,000,000 文字まで。

## エージェント（MCP と REST）

スコープ `weekly_notes:read` が要る。読み取りのプリセット（読み取り専用・提案する・作業するエージェント）に含まれる。

**既存のトークンには付かない。** スコープは作成後に変えない決まりのため（権限が後から広がる経路をなくす、[agent-gateway.md](./agent-gateway.md)）。週次ノートを読ませるには、プリセットでトークンを作り直す。`daily_plans:read` に含めなかったのも同じ理由。

| 入口 | 内容 |
| --- | --- |
| MCP `get_weekly_note` | `date`（週のどの日でもよい。省くと今週）の週の `{week_start, week_end, note, daily_notes}`。週は Web と同じ順番で決める。`note` は `{id, updated_at, content_markdown}`、無いか空なら `null`。`daily_notes` はその週の日次ノートの `{date, title}`（`daily_plans:read` があるときだけ。無ければ `null`）で、`get_daily_note` で本文を読む |
| MCP `list_weekly_notes` | 空でないノートを新しい週から `limit`（1〜12、既定4）件、Markdown で。`date_from`・`date_to` は任意の日で、7日間が範囲に重なる週を返す。`has_more` があれば、いちばん古い `week_start` の前日を `date_to` にして続きを読む |
| REST `GET /api/agent/v1/weekly-notes` | `(updated_at, id)` 順のページ（ほかの一覧と同じ差分同期）。本文は HTML のまま。空のノートも返す（空にしたことを差分で拾えるように） |

各ノートの `week_start`・`week_end` は、そのノート自身の7日間。MCP は context note と同じ変換（`note_html_to_markdown`）で Markdown にする。書き込みのツールはまだない。

## 週次レポートとの関係

週次レポート（`/scheduling/weekly-report`）は開始日を自由に選べ、その日から7日間を集計する。開始日の初期値と「今週」ボタンは、この設定での今週の始まり（例: 水曜始まりなら直近の水曜日）にする。設定を読み込めないときは今日。

## 日次ノートを MCP から読む

`get_daily_note`・`list_daily_notes`（`daily_plans:read`）。日次ノートのブロックを、エディターの並び順のまま Markdown にする（`daily_note_markdown.py`）。本文のリッチテキストは HTML を経由して context note と同じ変換で Markdown にする。予定・休憩・`/schedule`・チェックリストは1行ずつの箇条書きで、タスクを指す行には `(task_id: ...)` か `(quick_task_id: ...)` を付け、`get_task` で読めるようにする。行のメモはその下に字下げして続ける。

## データ

マイグレーション `043_add_weekly_notes.sql`:

- `weekly_notes`: ユーザーと `week_start` で一意（`uq_weekly_notes_user_week`）。設定を変えた後も古いノートを残すため、`week_start` の曜日は DB で縛らない（作るときの曜日は API が確かめる）。ユーザーを削除するとノートも削除する。RLS は所有者の行だけを許可する。
- `user_settings.week_start_day`: `sunday`（既定）〜 `saturday` の7つ（CHECK）。旧 API が作る設定の行には既定値が入る。

## 展開手順

1. `043_add_weekly_notes.sql` を適用する（追加のみで、旧 API はこのテーブルと列を読まない）。**API より先に適用する**: 新しい API は `user_settings` を読むときに `week_start_day` 列を使う。
2. API、次に Web をデプロイする。追加の環境変数やパッケージは不要。
3. `/notes/weekly` で書いて保存し、再読み込みで残ることを確かめる。設定ページの「週の始まり」を変えて、書いたノートの期間が変わらないこと、ノートのない週が新しい始まりになることを確かめる。`weekly_notes:read` を持つトークンで MCP の `get_weekly_note` を呼び、Markdown が返ることを確かめる。

ロールバックは Web と API を戻してから `043_add_weekly_notes_rollback.sql` を適用する。週次ノートと週の始まりの設定はすべて消えるので、残すなら先に `weekly_notes` をバックアップする。

## 対象外（今後）

- MCP からの書き込み（例: 週の終わりにエージェントが振り返りを追記する `append_weekly_note`）。
- 週次ノートのテンプレート（「今週の目標」「振り返り」などの見出しを最初に入れる）。
- 週の作業ログの集計（週次レポート）や週のリズムの予定時間を、週次ノートの横に出すこと。
- 週次ノートの全文検索と、データエクスポート・バックアップへの追加。
